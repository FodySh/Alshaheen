# الأمان: الدخول والجلسات

## المصادقة بخطوتين (تطبيق مصادقة TOTP)

- **إلزامية لفريق المكتب** (وسيط ومدير). من لم يفعّلها يُحوَّل إلى `/mfa/setup` قبل فتح لوحة المكتب.
- **اختيارية للعملاء** من «حسابي ← الأمان». من فعّلها يُطلب منه الرمز عند كل دخول، ولا يستطيع إلغاءها إلا برمز حالي.
- عند الربط تُغلق كل الجلسات الأخرى، ويصل صاحب الحساب بريد تنبيه. وكذلك عند الإلغاء أو إعادة الضبط.
- **فقدان الجوال:** يعيد المدير ضبط مصادقة الموظف من «الفريق». هذا يحذف التطبيق المرتبط وينهي كل جلسات الموظف. إن فقد **المدير الوحيد** جواله، احذف عامل المصادقة من لوحة Supabase: Authentication ← Users ← المستخدم ← Factors.

### الفرض في قاعدة البيانات، لا في الواجهة فقط

كل صلاحيات الموظف تمر عبر `is_staff()` و`is_admin()`. تشترط الدالتان جلسة `aal2` تحقق فيها الرمز خلال آخر 12 ساعة (`session_is_mfa_fresh()`). لذلك لا تكفي كلمة مرور مسروقة للوصول إلى بيانات المكتب، حتى عبر الواجهة البرمجية مباشرة.

## الجلسات

| | جلسة عادية (aal1) | جلسة موثقة بخطوتين (aal2، كل الموظفين) |
| --- | --- | --- |
| الخمول | 14 يوماً | 30 دقيقة |
| العمر الأقصى من الدخول | 30 يوماً | 12 ساعة (وتفرضه قاعدة البيانات أيضاً) |

- يفحص الـ proxy الحدود مع كل طلب، والسياسة في `src/lib/session.ts`. عند تجاوز حد يُلغي الجلسة على خادم Supabase، فلا يصلح رمز التجديد بعدها، ثم يعيد التوجيه إلى `/login?expired=…`.
- **وقت الدخول** يُقرأ من `amr` في رمز JWT الموقّع، فلا يمكن التلاعب به.
- **آخر نشاط** يُحفظ في كوكي `sh_seen` (HttpOnly). يحمي من جهاز تُرك مفتوحاً، لا من مهاجم يملك الكوكيز. العمر الأقصى هو الحد الصلب.
- **كوكيز Supabase:** ‏`Secure` في الإنتاج، و`SameSite=Lax`، وعمرها 30 يوماً بدل 400. ليست HttpOnly لأن رفع الصور والمرفقات يتم من المتصفح بجلسة المستخدم.
- **تغيير كلمة المرور** يغلق الجلسات الأخرى ويرسل بريد تنبيه. **رابط تعيين كلمة المرور** لا يكفي لمن فعّل المصادقة بخطوتين: يُطلب الرمز أولاً.
- «اخرج من كل الأجهزة» في «حسابي» ينهي كل الجلسات.

## حمايات أخرى

- `safeNext` يرفض إعادة التوجيه لمواقع خارجية، بما فيها `/\evil.com` الذي يعامله المتصفح كـ `//evil.com`.
- `/auth/signout` يرفض الطلبات من مواقع أخرى (CSRF).
- ترويسات الأمان في `next.config.ts`:
  - CSP: ‏`frame-ancestors 'none'` و`object-src 'none'` و`base-uri 'self'` و`form-action 'self'`، والاتصال محصور بالموقع وSupabase.
  - HSTS و`nosniff` و`X-Frame-Options` و`Referrer-Policy` و`Permissions-Policy`.
- **سر المهمة المجدولة** يُقارن بزمن ثابت.

## الاختبارات

```bash
npm test                                      # سياسة الجلسات وsafeNext ورمز التطبيق

npm run build && npx next start -p 3100       # فحص شامل على المشروع الحقيقي:
node --env-file=.env.local scripts/security-e2e.mjs http://localhost:3100
```

الفحص الشامل ينشئ حساب اختبار مؤقتاً ويحذفه في النهاية.

اختبار سياسات قاعدة البيانات في `supabase/tests/mfa_enforcement.sql`. يُشغَّل في محرر SQL، ويحاكي رموز JWT مختلفة لحساب المدير، ثم يُلغي كل شيء وتظهر النتيجة في رسالة الخطأ.

## إعدادات يُنصح بها في لوحة Supabase (Authentication)

- **Multi-Factor ← TOTP:** مفعّل. هو الافتراضي، وتحقق منه الفحص الشامل.
- **Attack Protection:** فعّل حماية كلمات المرور المسربة (Leaked password protection)، واجعل الحد الأدنى 8 أحرف أو أكثر.
- **Rate Limits:** طلبات الدخول تمر من خوادم Vercel، فيتشارك المستخدمون حد عنوان IP نفسه. أضف قاعدة حد معدل في Vercel Firewall على `POST /login` و`/mfa/verify`.
